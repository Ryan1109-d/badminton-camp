## 後端部署（Google Apps Script）

1. Google Sheet 建立分頁 `報名名單`，第一列填**這 27 欄**，順序不能動（程式按位置寫入）：

   ```
   報名時間 | 梯次 | 時段 | 學員姓名 | 性別 | 年齡 | 年級 | 收信信箱 | 緊急聯絡人 | 緊急聯絡人電話 |
   繳款人姓名 | 繳款人電話 | 繳款人信箱 | 優惠身份 | 推薦人 | 午餐 | 狀態 | 團報成員 | 衣服尺寸 |
   備註 | 照片同意 | 健康狀況 | 健康說明 | 緊急醫療授權 | 法定代理人聲明 | 繳費通知 | 系統訊息
   ```

   與足球營（26 欄）的差別只有第 3 欄多一個「時段」，其餘相同。

   > ⚠️ 第 15 欄「推薦人」是 2026-08-17 新增的。若 Sheet 已有報名資料，
   > 請用「插入 1 欄」而不是直接改標題，否則其後的既有資料會全部錯位。

2. 擴充功能 → Apps Script → 貼上 `gas-backend.js`
3. 填 `CONFIG.SHEET_ID`（repo 內是 `YOUR_SHEET_ID_HERE` 佔位字串，真值只填在 Apps Script）
4. 部署為網頁應用程式（執行身分：我；存取權：所有人），複製 Web App URL 填進 `signup.html` 的 `GAS_URL`
5. 函式下拉選 `installDailyBackupTrigger` → 執行，裝每日 23:00–00:00 備份

> ⚠️ **重貼原始碼前先複製 Apps Script 上現有的 `SHEET_ID` 與 `PAYMENT.ACCOUNT_NAME`**。repo 這份兩者都是佔位字串，直接覆蓋會清掉設定，繳費通知會被防呆擋住。
>
> ⚠️ 本站的真實 `SHEET_ID` 曾經 commit 進 public repo（git 歷史刪不掉），**Sheet 本身的共用權限是唯一防線**，務必設為「僅限有存取權的使用者」。備份副本會繼承來源權限，也要確認為「限制」。

## 主要函式

| 函式 | 作用 |
|---|---|
| `doPost` | 接收報名，寫入 Sheet、判定正取／候補、寄確認信 |
| `sendConfirmEmail` / `sendWaitlistEmail` | 報名確認信／候補通知信 |
| `notifyOwner_` | 每筆新報名寄一封通知到 stayyoung985，主旨帶【羽球】以免與足球混淆。寄失敗不影響報名 |
| `calcAmount` / `buildPaymentBody` | 依報名時間、時段、優惠身份與推薦人算金額、組繳費通知內容。回傳的 `refundable` 是推薦人優惠金額，**不含在 `total` 內**，為開課首日現場要退的現金；繳費信會另起一段說明 |
| `previewPaymentNotice` | **預覽**繳費通知（不寄出），上線前先跑這個 |
| `sendPaymentNotice` | 寄繳費通知 |
| `sendCancelNotice` | 取消通知 |
| `paymentIsPlaceholder` | 戶名還是佔位字串時擋住所有繳費通知 |
| `installDailyBackupTrigger` / `listTriggers` / `dailyBackup` | 每日備份（只留最近 14 份） |

## 個資保護

報名資料含姓名、電話、信箱、緊急聯絡人與**健康狀況**（敏感個資）。防護重點：

**對外只有一個入口。** `doPost` 收報名、`doGet` 回固定字串，**沒有任何讀取報名資料的對外端點**。拿到 Web App 網址的人只能送報名，不能撈資料。日後要加後台請走 Google 帳號授權，不要做成「知道網址就能看」。

**要定期跑的函式：**

| 函式 | 作用 | 會動到資料嗎 |
|---|---|---|
| `checkPrivacy()` | 檢查 Sheet 與每日備份有沒有對外開放、還有誰有存取權 | 唯讀，安全 |
| `lockDownSharing()` | 把 Sheet、備份資料夾與所有副本壓成「只有我」 | 會改共用設定 |
| `purgeOldData()` | 依報名表告知的保留期限試算要刪什麼 | 試算，不刪 |
| `purgeOldData(true)` | 真的刪 | **不可逆** |

**備份副本是最容易漏掉的破口**——它會繼承來源 Sheet 的共用設定。`dailyBackup()` 現在每次都明確把副本壓成私有，不倚賴繼承。

**防濫用：** honeypot、全域流量上限（`MAX_SUBMITS_PER_MINUTE`）、重複送出冷卻、白名單驗證、`safeCell()` 防公式注入、`safeText()` 防信件標頭注入。

**保留期限：** `CONFIG.DATA_PURGE_AFTER` 記錄報名表承諾的刪除日期，`purgeOldData()` 未到期不執行。

**前端：** 兩頁都有 Content-Security-Policy。換字型、換圖床、換 GAS 網址時要同步更新，否則資源會被擋。
